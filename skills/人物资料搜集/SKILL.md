# 人物资料搜集

## 一、适用范围

本技能用于为一组指定人物建立结构化资料档案，典型使用场景：

- 政府/园区/监管部门领导、企业负责人的背景资料整理
- 需要研判某位人物施政关注点、分管领域、公开表态风格
- 跨地区、跨部门任职经历复杂的人物，需要按任职阶段梳理公开活动与发言
- 拟接触、拟汇报、拟合作对象的前期尽调（公开信息层面）

不适用于：涉及个人隐私的非公开信息（家庭、住址、联系方式、健康状况）、需要付费数据库或内部档案才能获取的信息。

## 二、七条强制约束

以下约束为硬性要求，任何一条不满足即视为任务未完成。

### 约束 1：搜集范围必须覆盖全部任职阶段（纵向到底）

**常见错误**：只搜集人物当前职务上的公开活动，导致资料"看起来很多但缺少过往表现"。

**正确做法**：以履历为纲，逐段回溯，每个任职阶段都要单独检索。

- 先建立完整履历（含所有单位、层级、起止时间），再按阶段逐一检索
- 每个阶段至少检索一轮，重要岗位（一把手、分管产业/宣传/网络的副职）检索 2—3 轮
- 阶段划分示例：市级机关期 → 区属街道期 → 区属部门期 → 区级副职期 → 区级常委期 → 现职期
- 对没有公开记录的阶段，明确写"该阶段无公开活动记录可查"，不得跳过不提

### 约束 2：检索渠道必须横向铺开（横向到边）

单一渠道必然遗漏。每个关键事实至少尝试以下渠道中的两类以上：

| 渠道类型 | 具体来源 |
|---|---|
| 政府官网 | 国家部委、省/市级政府、区县政府门户网站（领导介绍页、政务动态、会议信息、任免公告） |
| 权力机关官网 | 人大、政协、法院、检察院网站（任免、审议、专题协商、判决） |
| 党委部门官网 | 区委/市委组织部、宣传部、统战部、网信办等 |
| 行业协会与社团 | 行业协会、学会、商会、基金会官网及公众号 |
| 企业官网 | 被调研企业、合作企业的官网新闻与公众号（常独家披露领导表态） |
| 官方媒体 | 党报党刊、通讯社、电视台、政府主办新闻网站 |
| 市场化媒体 | 主流财经/时政媒体及其转载 |
| 公众号与自媒体 | 政务公众号、街道/园区公众号、企业公众号、行业公众号（正文常被微信验证页拦截，优先找政府 / 党校 / 北京号的同源版本） |
| 百科类 | 百度百科、360 百科、搜狗百科（仅作线索与兜底，不作唯一依据） |

检索技巧：
- 用 `site:` 限定官方域名（如 `site:gov.cn`、`site:bjhd.gov.cn`）
- 姓名 + 职务、姓名 + 单位、姓名 + 活动类型（调研/座谈/签约/致辞/发布会）组合检索
- 姓名易重名时，叠加地域、单位、职务限定词
- 政府网站的站内搜索、栏目归档页、年度会议纪要往往是唯一出处

### 约束 3：信源必须交叉核验（可信度）

- **单一信源不足以采信**，除非该信源为一级官方信源（政府/人大/政协/法院官网的原始发布）
- **双源规则**：关键事实（职务任免、出生年月、学历、分管、明确表态）应有 2 个及以上独立信源，或 1 个一级官方信源
- **原始优先**：优先引用活动主办方/发布方的原始报道，而非转载稿
- **冲突处理**：两个信源冲突时，以一级官方信源为准；同级别冲突时，取时间最近、发布主体更权威者
- **不得推断**：不得根据"活动主题像谁分管"推断分管领域，不得根据姓名推断性别。无法确认时，写"未公开"或不写

详细分级与判定标准见 `references/source-rules.md`。

### 约束 4：日期必须核验到年月日（准确性）

错误日期会直接毁掉整份材料。每条活动必须核验：

1. **页面发布日期**（页面顶部/底部"发布时间"）
2. **URL 路径中的日期**（如 `t20240528_4816385`、`/2024-06/12/`）
3. **正文内的时间表述**（"6月24日""日前""近日""昨天"）

三者必须自洽。核验方法：
- 正文只写"月日"时，用页面发布年份或 URL 年份补全年份
- 正文写"近日""日前""昨天"时，以页面发布日为锚点，标注为"（近日）"或取发布日
- 正文日期与 URL/发布日跨年矛盾时，以后者为准重新计算
- 转述型报道（回访、回顾、周年综述）中的日期不是活动发生日，必须标注报道时间并说明
- 无法确定年份的活动，宁可不收录，或明确标注"具体日期未披露"

### 约束 5：不确定的内容不写入（洁净度）

- 检索不到官方信息的基本信息项，写"未公开"，并在该人物章节末以一句话说明"经多轮检索，官方渠道未公开"
- 两个信源互相矛盾且无法判断的字段（如入党时间两个年份），整项不写入正文表格，避免把不确定性带入结论
- 不写"待核实""疑为""可能""推测"等中间态表述，要么确认写入，要么不写
- 不写施政研判、接触建议、优劣势分析，除非用户明确要求单独成章

### 约束 6：只陈述事实，不作主观判断（客观性）

- 只写"谁、何时、何地、以什么身份、说了什么、做了什么"，到此为止
- 禁止一切推断性表述：不得由活动内容反推分管领域（如"他多次出席科技活动，说明分管科技"），不得推测动机、立场、派系、晋升前景
- 分管/分工优先引用官方文件的原文表述；没有分工文件时，可以引用本人署名文章、单位公众号中对自己的职责表述，注明出处；仍不得用活动频次、会议座次、出席规格推断
- 不对信息作评价性排序（"最重要的发言""核心表态""信号明显"），不判定重要性等级
- 不给接触建议、不给风险评级、不给"研判""启示""对策"类段落，除非用户明确要求另立一章并标注为主观分析
- 多个信源对同一事实有不同表述时，并列原文并注明各自出处，不自行择一"综合"

### 约束 7：只用合法公开渠道，不绕过任何技术保护措施（合规性）

- 只采集公开可访问的信息：无需登录、无需付费、无需内部权限即可获取的页面、文件与报道
- 遇到设置了口令、权限限制、加密保护的文件，只使用其提供方给出的正常阅读途径（官网 HTML 正文页、公报阅读页、官方另行发布的可读副本、权威媒体的全文转载）；不得使用解密库、破解工具、去除权限限制或格式转换绕过限制等手段提取内容
- 判断标准：读者用一台普通电脑、以发布方预期的方式能否打开。能，则属正常阅读；需要额外技术手段才能打开，则放弃该文件
- 放弃受限文件时，在检索记录中注明"该文件受访问限制，未采用"，并说明改用了哪一个可读载体
- 不采集非公开信息：内部文件、未公开的任免材料，以及身份证号、住址、家庭成员、联系方式、健康与财务状况等个人隐私
- 不绕过网站访问控制与反爬机制，不伪造身份、不调用未授权接口
- 引用政府文件时注明文号、发布机构与原文链接，便于回溯

## 三、工作流程

### 第 1 步：明确对象与用途

确认：人物名单、所在单位与层级、文档用途（内部参阅/汇报/尽调）、是否需要横向对比。

### 第 2 步：先建"骨架"——履历与职务

1. 检索官方领导介绍页、任免公告、干部公示、百科词条，交叉拼出完整履历
2. 履历必须带起止时间（精确到月即可，个别精确到日）
3. 标注每个阶段的单位层级与职务性质（一把手/副职/兼任/主持工作）
4. 履历存疑处（如"某年某月起任某职"两源不一致）取官方任免文件时间

### 第 3 步：按阶段检索公开活动与发言

对履历中每一段任职：
1. 用"姓名 + 单位 + 活动类型"组合检索，政府官网优先
2. 逐条记录：日期、场合、身份表述、同场人员、核心表态（原文引语）、来源链接
3. 同一活动有多个报道时，取信息最全者为主源，其余作为交叉验证
4. 优先保留**有实质内容的表态**（工作部署、政策取向、对企业的承诺），弃用纯礼节性出席

### 第 4 步：交叉核验与清洗

1. 逐条检查双源规则，补第二信源
2. 逐条核验日期（发布日/URL/正文三者自洽）
3. 删除无法核验的条目；矛盾字段按约束 5 处理
4. 检查是否有把"转述""回顾""媒体推测"当成事实写入的情况

### 第 5 步：按模板成文

严格按 `references/format-spec.md` 的结构输出；文件命名建议：`<地区/单位>重点人物资料-<姓名1>·<姓名2>-<YYYYMMDD>.md`。

### 第 6 步：交付前自检

逐项打勾（见第五节自检清单），任何一项不通过则返工。

## 四、文档结构（摘要）

完整格式规范见 `references/format-spec.md`，单人档案模板见 `templates/人物档案模板.md`。

每位人物固定五章：

1. `## x.1 基本信息`——表格：姓名、性别、民族、出生日期、籍贯、政治面貌、入党时间、参加工作时间、学历、学位、毕业院校、专业、其他任职
2. `## x.2 现任职务`——职务全称、兼任职务表、分管工作、是否晋升、是否本地晋升、任职起止
3. `## x.3 职务任免`——时间 + 事项两列表格
4. `## x.4 履历`——时间 + 职务两列表格，按时间正序
5. `## x.5 公开活动与发言`——按任职阶段分组，阶段内按时间倒序；每条含日期、场合、身份、同场人员、原文引语、来源链接（多源并列）

## 五、交付前自检清单

- [ ] 每个人物的履历是否完整到"从参加工作至今"，无断裂年份
- [ ] 是否按每个任职阶段都做了检索，而不是只查现职
- [ ] 活动条目是否都带年月日，且日期经三种方式核验
- [ ] 每条关键事实是否满足双源或一级官方信源
- [ ] 引语是否为原文，未做改写、拼接、语气强化
- [ ] 是否残留"待核实""推测""疑为"等中间态表述（应为 0）
- [ ] 未公开字段是否统一写"未公开"而非留空
- [ ] 文末是否列出/标注来源，链接可访问
- [ ] 是否混入了研判、建议、评价等主观内容（除非用户要求）
- [ ] 是否出现由活动反推分管、由出席规格推断层级的表述（应为 0）
- [ ] 是否使用了需要解密/绕过权限才能打开的文件（应为 0）
- [ ] 受限文件是否已注明"受访问限制，未采用"并说明替代载体
- [ ] 是否采集了隐私信息（身份证、住址、家庭、联系方式、健康、财务）（应为 0）
- [ ] 人物之间格式是否完全一致（同名章节、同列数表格、同样条目结构）

## 七、常见失败模式（务必规避）

| 失败模式 | 后果 | 规避方式 |
|---|---|---|
| 只搜现职活动 | 资料单薄，看不出人物一贯取向 | 按履历逐段回溯 |
| 用百科当唯一来源 | 出生年月、入党时间常见错漏 | 百科只作线索，必须回到官方源 |
| 把"近日"直接写成具体某日 | 日期错误，被引用后放大 | 以发布日为锚点，或标注"（近日）" |
| 把回顾报道的刊发日当成活动日 | 时间线错乱 | 区分"活动发生日"与"报道刊发日" |
| 把媒体转述写成直接引语 | 引语失真 | 只摘引号内原文，不改写 |
| 用活动主题反推分管领域 | 结论无依据 | 分管只认分工文件或官方表述 |
| 为读一份加密/受限文件而使用解密库 | 越界，且往往违反使用条款 | 放弃该文件，改用官网正文页或权威媒体全文 |
| 用"交叉印证"掩盖推断 | 多个推断互相支撑仍是推断 | 推断一律不写，只写官方原文表述 |
| 多人物格式不统一 | 阅读与对比困难 | 全部套用同一模板 |

## 八、检索矩阵与覆盖度（全面搜索必须做）

只按姓名搜一轮，必然漏掉一半。下面每一类至少跑一轮，把结果并进履历与活动底稿：

| # | 检索式 | 目的 |
|---|---|---|
| 1 | 姓名 + 职务 / 单位 / 活动类型 | 找现职活动与表态 |
| 2 | 现任与历任职务全称 + 地区 | 很多报道只写职务、不写姓名 |
| 3 | 单位 + 年份 + 活动 | 从最早可确认任职年份逐年查到今年 |
| 4 | 姓名 + 年份 | 逐年补齐 |
| 5 | 关联条线：宣传、网信、互联网行业党委、网络安全宣传周、数字经济 / 游戏电竞、普法、防汛、统战 | 找跨部门、跨条线的露面 |
| 6 | 名单类：防汛指挥部、专项工作组、领导小组、普法协调小组、网信委 | 确认职务、排序、在任时点 |
| 7 | 署名文章：区直机关党建、北京日报 / 前线 / 支部生活、学习强国、单位公众号 | 找本人对自己职责的表述 |
| 8 | 公众号与融媒体：北京号、区政府 / 融媒体中心、街道 / 园区、企业 / 协会公众号 | 官网不转载的活动常只在这里；公众号正文被验证页拦截时找同源版本 |
| 9 | 行业活动与协会：ChinaJoy、DEAS、游戏工委、音数协、MGEA 等 | 找产业条线的实质接触 |
| 10 | `site:` 限定政府域名逐个站内搜索 | 防止搜索引擎漏收 |

**公众号（mp.weixin.qq.com）验证页怎么处理**：

- 先用插件工具 `character_profile_wechat_search`（搜狗微信）按关键词 / 活动名 / 标题搜公众号，拿到标题、摘要、发布时间、公众号名和跳转链接；摘要只是线索，不是全文。
- 微信会对非微信环境返回 `/mp/wappoc_appmsgcaptcha`，或「环境异常 / 当前环境异常，完成验证后即可继续访问 / 去验证」页面；这不是文章内容，不能引用。
- 识别到上述任一特征，最多重试 1 次；仍失败就放弃这个链接，不要反复抓同一个 URL，也不要用标题猜正文。
- 改用同源版本：区政府 / 区委官网、区委党校、北京组工网、北京号、区融媒体中心、部门官网、北京市政府网，以及主流媒体的转载。
- 搜索方法：拿文章标题做精确搜索，叠加 `site:`；或「活动名 + 日期 + 单位」。北京号版本不一定在 mp.weixin，可能在政府网站或融媒体域名下。
- 公众号链接只作线索（标题、日期、发布号）；正文事实必须来自可访问的官方 / 党媒 / 北京号版本，或用户提供的原文。只有公众号、又找不到同源版本时，这条活动不收。

**覆盖度下限**（全面搜索；低于它撑不起后续画像分析）：

- 五章齐全；任职阶段 ≥ 2 个，每个阶段 ≥ 3 条活动，确无记录写明"该阶段未见公开活动记录"
- 公开活动与发言 ≥ 12 条；独立信源 ≥ 10 个，其中官方域名 ≥ 3 个
- 兼任职务逐个查，每条注明证据；现任职务给出"任职起始时点"（用最早公开报道倒推，注明是在任时点）
- 署名文章、名单类、会议纪要都算记录；纯礼节性、单源自媒体的活动可以不收

粗略搜索的下限：活动 ≥ 3 条、信源 ≥ 3 个、官方域名 ≥ 1 个，只跑矩阵第 1、2、4 类加一次名单检索。

安装本 skill 的「人物情报库」插件会在保存时按这些数字检查，不达标会拒绝入库并列出缺口；确实查不到的，要在说明里写清已跑过哪些渠道。
